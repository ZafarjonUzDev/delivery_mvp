# API Contract V1.0 (dastlabki)

**Asos:** Django Templates SSR, faqat interaktiv qismlar uchun JSON endpoints. Names/paths taklif, kelishilgach OpenAPI/Swaggerga tushiriladi. Barcha yozuvchi operatsiyalar server-side validation + session/CSRF yoki validated Telegram session. Response `application/json`. Davlatlar API orqali qo‘lbola set qilinmaydi: status transition endpoint qo‘llanadi.

## JSON convention

Muvaffaqiyat: `{"data": {...}}` yoki `{"data": [...], "meta": {...}}`. Xato: `{"error": {"code": "PRICE_CHANGED", "message": "Narx yangilandi", "fields": {}}}`; `400/401/403/404/409/429` farqlanadi. API foydalanuvchi tilini account/session or Accept-Language'dan oladi.

| Method + URL (draft) | Auth | Maqsad |

## Sample transitions

| from | to | actor | reason |
|---|---|---|---|
| NEW | CONFIRMED | branch admin | optional |
| NEW | CANCELED | branch admin | required |
| NEW | CANCELED | customer (token/ownership) | reason optional or selected (review) |
| CONFIRMED | PREPARING | branch admin | optional |
| PREPARING | READY | branch admin | optional |
| READY | COMPLETED | branch admin | optional |
| CONFIRMED/PREPARING | CANCELED | responsible admin | required |
| READY | CANCELED | owner/explicit manager | required |

Unauthorized transitions -> `403`, stale transition / terminal order -> `409`, not found or not owned -> `404` (avoid object enumeration). API spec generated by DRF schema / drf-spectacular after implementation.

## Security contract

- Guest cart and checkout tied to active Django session cookie; CSRF protected.
- Tracking URL unpredictable token; token hash database, rate limit token attempts; private fields minimized; no ordering by sequential ID fallback.
- Telegram initData signature/hash and auth_date TTL verification on server, Telegram-only feature flag gate.
- Admin branch scope always queryset filtered; global owner can access only this deployment/business.
- Rate-limit OTP request/verify and checkout; never expose OTP in logs, return messages not revealing phone registration.
- XLSX export cannot expose arbitrary model fields, allow only explicitly approved columns and bounded date ranges; formula injection values sanitized.
